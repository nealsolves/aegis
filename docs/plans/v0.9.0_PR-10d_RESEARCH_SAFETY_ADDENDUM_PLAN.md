# AEGIS `v0.9.0` PR-10d Research Safety Addendum Plan

Date: 2026-05-03
Status: Proposed
Target branch: `feat/v0.9-10d-research-safety-addendum`
Placement: after PR-10a, PR-10b, and PR-10c; before PR-11 beta freeze

---

## Intent

PR-10d is a bounded, research-informed hardening addendum for the `v0.9.0` beta train.

It incorporates the strongest recent agent-safety and workflow-governance ideas into surfaces that already exist in the beta line:

- `aegis workflow lint`
- `aegis workflow doctor`
- `aegis workflow trace`
- `aegis workflow export`
- workflow starter safety tests
- optional adapter fixtures and fail-closed tests
- internal validator-hook examples

This PR must not reopen the product scope. It must not turn AEGIS into a hosted runtime, orchestrator, transport proxy, MCP gateway, streaming runtime, memory manager, or LLM-as-judge platform.

The purpose is simple:

> strengthen the workflow governance beta before PR-11 without weakening the default adopter path.

## Research Inputs

The addendum is informed by recent work in agent safety, workflow verification, tool-use governance, memory poisoning, multi-agent risk, auditability, and misuse benchmarking.

These papers are research inputs, not dependency requirements:

| Research theme | AEGIS implication |
| --- | --- |
| Temporal constraints for LLM agents | Add lightweight temporal/sequence linting using existing workflow DSL fields. |
| Static verification of agent workflow graphs | Add graph/topology lint findings and witness traces. |
| Verifiably safe tool use and capability labels | Strengthen participant, capability, trust, side-effect, and approval checks in adapter fixtures and docs. |
| Multi-agent verification | Provide internal multi-aspect `ValidatorHook` examples without making LLM judging a core engine. |
| Memory poisoning and memory-injection research | Add source/provenance warnings and starter guidance; defer full memory governance. |
| Multi-agent interaction and graph-risk work | Add topology checks for loops, authority widening, recursive reuse, and approval bypass. |
| Audit-trail accountability research | Add richer governance rationale and decision-basis metadata to workflow export. |
| Agent misuse benchmarks | Add small governance smoke tests, not imported benchmark suites. |

## Workstream 1 — Graph and Topology Lint

Enhance `aegis workflow lint` with graph checks derived from existing workflow policy fields.

Inputs:

- `workflow.required_sequence`
- `workflow.allowed_transitions`
- `workflow.handoffs`
- `workflow.participants`
- `workflow.escalation`
- `workflow.max_steps`
- `workflow.max_total_tool_calls`
- `workflow.protocol_constraints`

Add findings:

| Code | Meaning | Expected evidence |
| --- | --- | --- |
| `WORKFLOW_UNREACHABLE_STEP` | A declared step cannot be reached from the start path. | `witness_trace`, `declared_step`, `known_predecessors` |
| `WORKFLOW_DEAD_END_STEP` | A non-terminal step has no valid next step. | `witness_trace`, `step_id`, `valid_next_steps` |
| `WORKFLOW_REQUIRED_SEQUENCE_IMPOSSIBLE` | `required_sequence` conflicts with transitions or budgets. | `required_sequence`, `conflicting_rule`, `next_action` |
| `WORKFLOW_APPROVAL_BYPASS` | A path reaches a sensitive/terminal step without required approval. | `witness_trace`, `approval_rule`, `bypass_path` |
| `WORKFLOW_UNBOUNDED_HANDOFF_LOOP` | Handoff cycle exists without a budget or approval break. | `participants`, `cycle`, `budget_rule` |
| `WORKFLOW_TOOL_BUDGET_INFEASIBLE` | Declared tool budget cannot support the required path. | `max_total_tool_calls`, `minimum_required_calls`, `next_action` |

Rules:

- These checks must be deterministic.
- These checks must use existing DSL fields only.
- No new public DSL is required in PR-10d.
- Findings should be warnings or errors according to existing lint severity conventions.
- Every graph finding must include a plain-English `message` and a bounded `witness_trace` where applicable.

## Workstream 2 — Temporal Checks Without a New Temporal DSL

Implement a lightweight temporal-check layer over the existing DSL.

Examples:

- `authenticate` must precede `retrieve_sensitive_context`.
- `review` must precede `publish`.
- `approval` must precede external handoff or externalizing capability.
- source/grounding step must precede briefing/finalization where the starter marks source-required behavior.

Implementation rule:

> Do not introduce a temporal-logic language in `v0.9.0`. Express checks as derived lint rules over `required_sequence`, `allowed_transitions`, `escalation`, participant metadata, and starter profile metadata.

---

## Workstream 3 — Source and Memory Provenance Warnings

Add doctor/lint warnings for memory-like or source-derived context without provenance.

Possible warning code:

- `WORKFLOW_SOURCE_PROVENANCE_WARNING`

Trigger examples:

- workflow artifact references source-required starter metadata but completed steps lack source/provenance metadata
- invocation context contains memory-like fields without `source_ids`
- a generated briefing/final output step is completed without evidence of source-bearing predecessor steps

Rules:

- This is not full memory governance.
- This must not block the default path unless the existing starter or policy already marks source evidence as required.
- The recommendation should explain how to attach source IDs or mark a step as non-evidence-bearing.

---

## Workstream 4 — Workflow Export Governance Rationale

Enhance `aegis workflow export` output with optional rationale metadata.

Add backward-compatible fields under each step summary or session summary:

```json
{
  "governance_rationale": "approval_required_before_external_handoff",
  "decision_basis": ["allowed_transitions", "approval_checkpoint", "tool_budget"],
  "operator_action": "approval_granted",
  "approval_checkpoint_id": "...",
  "source_ids": ["..."],
  "waiver_id": null
}
```

Rules:

- Existing export consumers must remain compatible.
- Operator and audit modes may differ in detail level.
- Raw provider payloads must not be persisted by default.
- Integrity metadata must remain present.

---

## Workstream 5 — Adapter-Informed Capability and Trust Tests

After PR-10a, PR-10b, and PR-10c land, add fixture-based tests that verify optional adapters preserve the governance boundary.

Test themes:

- alias-backed Bedrock participant identity is required for governed binding
- A2A capability mismatch fails closed
- OpenAI Agents SDK wrapped-tool governance rejects unsupported surfaces explicitly
- externalizing or side-effect capability requires approval where policy demands it
- descriptive names are insufficient when authoritative binding is required
- remote participant cannot widen role, protocol, capability, or handoff authority

Rules:

- Fixture-only tests are preferred.
- No network calls.
- No provider credentials.
- No adapter becomes the default path.

---

## Workstream 6 — Internal Multi-Aspect ValidatorHook Example

Add a test/docs example showing how an internal validator hook can evaluate multiple aspects:

- source grounding
- schema semantics
- policy risk
- externalization risk

Rules:

- The hook remains internal in `v0.9.0` unless separately promoted.
- The host owns any external verifier calls.
- AEGIS only records hook result, timeout, decision, provenance, and failure behavior.
- DENY, REVIEW_REQUIRED, TIMEOUT, and stale results remain fail-closed according to the existing hook contract.

---

## Workstream 7 — Safety Smoke Tests

Add a focused governance smoke-test suite.

Minimum scenarios:

1. Prompt-injection-like source instruction cannot override workflow policy.
2. External send/handoff blocks without required approval.
3. Multi-turn failure-and-fix path cannot bypass approval after resume.
4. Handoff loop is bounded by `max_steps` or explicit approval.
5. Tool budget cannot be exceeded through step composition.
6. Adapter capability mismatch fails closed.
7. Export shows governance rationale for blocked, paused, failed, and completed paths.

Suggested test file:

- `tests/test_pr10d_research_safety_addendum.py`
