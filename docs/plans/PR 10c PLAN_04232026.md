# PR-10c Implementation Plan — OpenAI Agents SDK Adapter

## Summary
- Ship `openai-agents` support as an advanced source-only beta module at `aegis.openai_agents_adapter`, behind a new `openai-agents` optional extra. Do not add top-level `from aegis import OpenAIAgentsAdapter` re-exports; keep the base `aegis` install and import path unchanged.
- Keep the host in charge of `Runner.run*`, provider choice, SDK sessions, retries, and approval decisions. AEGIS owns pre-run protocol and binding validation, wrapped-tool authorization, interruption checkpoint correlation, and additive workflow evidence.
- Replace the outdated tracing assumption in the current PR-10c docs: use a global `OpenAIAgentsTracingProcessor` registered via the SDK tracing API, and use `RunConfig.trace_metadata` plus local context to correlate traces back to `adapter_step_key`.

## Public API / Interface Changes
- Add `aegis.openai_agents_adapter` with:
  - `OpenAIAgentsAdapter`
  - `OpenAIAgentsParticipantBinding`
  - `OpenAIAgentsPreparedStep`
  - `OpenAIAgentsPendingApproval`
  - `OpenAIAgentsTracingProcessor`
- `OpenAIAgentsAdapter` methods:
  - `bind_graph(...)` as an optional preflight validator.
  - `prepare_step(...)` to validate the graph, clone the governed agent graph, wrap supported tools, inject `protocol_evidence.openai_agents`, inject `_aegis_openai_agents` correlation into context, and return a prepared step.
  - `pause_step(...)` to mirror SDK `interruptions` into `session.pause(...)`, mint and store the AEGIS checkpoint id, and return `OpenAIAgentsPendingApproval(run_state, checkpoint_id, interruptions)`.
  - `record_approval_decision(...)` to validate checkpoint correlation and call `session.resume(...)` or `session.deny_approval(...)`.
  - `complete_step(...)` to normalize final result evidence, merge trace summary, validate observed handoffs, and call `session.enforce_step_post_call(..., step_metadata=...)`.
  - `wrap_function_tool(...)` and `wrap_agent_as_tool(...)` remain public but are documented as advanced adapter helpers.
- Add two additive AEGIS seams:
  - `GovernanceSession.authorize_step_tool_call(...)`
  - `GovernanceSession.enforce_step_post_call(..., step_metadata: dict[str, Any] | None = None)`
- Extend `workflow.protocol_constraints` with `openai_agents`:
  - `require_trace` default `false`
  - `allow_hosted_tools` default `false`
  - `allow_agent_as_tool` default `true`
  - `require_unique_agent_names` default `true`

## Implementation Changes
- Packaging and docs:
  - Add `openai-agents` optional extra in `pyproject.toml`; leave `requirements.txt` unchanged.
  - Update release-truth docs and parity tests so `OpenAIAgentsAdapter` is an advanced source-only beta surface, not a `1.0`-only placeholder.
  - Add `docs/reference/external/OPENAI_AGENTS_ADAPTER.md`; do not touch the PR-07 first-adopter doc order or quickstart.
- Adapter runtime:
  - Use lazy SDK imports so base `aegis` import still works without the extra.
  - `prepare_step(...)` re-binds on every step; no persistent binding cache.
  - Infer `participant_id` from the root-agent binding when omitted; reject if the caller-supplied `participant_id` disagrees with the root binding.
  - Clone the governed graph with `Agent.clone(...)` so the caller’s agent objects are not mutated.
  - Traverse root, handoff targets, and nested agents referenced by wrapped `Agent.as_tool()`. Reject governed runs that use unsupported surfaces: `RealtimeAgent`, `SandboxAgent`, any `mcp_servers`, hosted tools, hosted MCP, tool-search or deferred-loading tools, or any tool family the adapter cannot intercept before execution.
  - Reject double-counting: if the invocation predeclares `tool_calls` for adapter-managed tools, `prepare_step(...)` fails before the run.
- Session and runtime enforcement:
  - Extend `GovernanceSession._pending_results[...]` with `adapter_step_key`, `dynamic_tool_calls_count`, `dynamic_tool_calls`, and step-level approval correlation.
  - `authorize_step_tool_call(...)` must read the effective policy from the pending inner `PreCallResult`, enforce allowed-tools and max-calls, increment session tool usage from real wrapped executions, and record only summary-form evidence.
  - Store adapter step metadata under each workflow step as `steps[i]["metadata"]`; keep the existing top-level step keys unchanged.
  - Reuse existing exception families and keep the frozen first-user reason-code list unchanged; only use adapter-specific `reason_code` values in exception details if an existing one cannot express the operator action.
- Tracing and evidence:
  - Register `OpenAIAgentsTracingProcessor(adapter)` globally via the SDK tracing API once per process.
  - `prepare_step(...)` must clone or create `RunConfig` to merge private `trace_metadata["_aegis_openai_agents"]`, default `group_id=session_id` when absent, preserve host-supplied `workflow_name` and `trace_id` when present, and reject immediately if trace is policy-required but tracing is disabled.
  - Treat trace as optional evidence unless `require_trace=true`; if optional and missing, persist `trace_present: false`.
  - `complete_step(...)` normalizes only summary evidence: protocol, adapter version, root and last agent names, observed agent sequence, observed handoffs, observed tool calls, interruptions summary, guardrail summary, usage summary, models seen, trace ids and group ids, and session-memory summary. Do not persist raw prompts, raw tool arguments, raw outputs, or raw trace blobs.
- Interruptions:
  - Use the explicit bridge selected here: `pause_step(...)` plus `record_approval_decision(...)`.
  - Keep one AEGIS step open across all pauses and resumes for the same top-level run; the host resumes with the same `prepared.wrapped_root_agent`, the returned `RunState`, the same AEGIS session, and the same SDK session instance or backing store.
  - Fail closed on checkpoint mismatch, stale paused state reuse, or resumed runs that do not map back to the active `adapter_step_key`.
- Trace and export surfaces:
  - `workflow export` operator mode already carries step metadata once it is stored on the step record.
  - Update `workflow trace` and `workflow export` audit mode to pass through optional `step_metadata` without changing existing keys or breaking artifacts that have no adapter metadata.

## Test Plan
- Unit tests:
  - import guard behavior with and without the `openai-agents` extra
  - schema validation and runtime defaults for `workflow.protocol_constraints.openai_agents`
  - duplicate agent-name rejection, missing root binding, unbound reachable handoff target, participant-role mismatch
  - unsupported-surface rejection for realtime, sandbox, MCP, hosted tools, tool-search and deferred-loading tools
  - wrapped `function_tool` authorization, wrapped `Agent.as_tool()` authorization, dynamic tool budget accounting, and double-count rejection
  - trace-required fail-closed behavior, optional-trace result-only behavior, and global tracing-processor correlation via `trace_metadata`
  - `pause_step(...)` and `record_approval_decision(...)` checkpoint matching, deny flows, and resumed `RunState` completion
  - `Runner.run_streamed(...)` terminalization after draining `stream_events()`
  - workflow step `metadata` persistence plus additive `workflow trace` and `workflow export` rendering
- Integration tests:
  - narrow live-SDK tests against the real `openai-agents` package for `Agent.clone(...)`, `function_tool`, `Agent.as_tool()`, handoff traversal, `RunState` interruption and resume, and tracing processor callbacks; no network-dependent OpenAI API calls.
- Verification:
  - `python -m pytest -v`
  - `flake8 aegis`
  - `python scripts/check_doc_parity.py`

## Assumptions And Defaults
- The adapter is a public beta submodule, not a top-level `aegis` re-export, and not part of the shipped `0.3.3` artifact.
- Hosted tools stay rejected in governed mode for PR-10c; there is no `observe_only` mode.
- Shared `AgentIdentity` and `AgentCapabilityManifest` work does not block PR-10c; ship OpenAI-specific binding dataclasses now and keep a later migration path open.
- The plan is aligned to the current official OpenAI Agents SDK docs for [running agents](https://openai.github.io/openai-agents-python/running_agents/), [results](https://openai.github.io/openai-agents-python/results/), [tools](https://openai.github.io/openai-agents-python/tools/), [handoffs](https://openai.github.io/openai-agents-python/handoffs/), [human-in-the-loop](https://openai.github.io/openai-agents-python/human_in_the_loop/), [sessions](https://openai.github.io/openai-agents-python/sessions/), [tracing](https://openai.github.io/openai-agents-python/tracing/), [run config](https://openai.github.io/openai-agents-python/ref/run_config/), and [run context](https://openai.github.io/openai-agents-python/ref/run_context/).
