# `v0.9.0` PR-10c Detailed Design Spec — OpenAI Agents SDK Adapter

Date: 2026-04-20
Status: Proposed
Baseline: PR-09 on `develop`

---

## 1. Release Context

AIGC `v0.9.0` already provides:

- `AIGC.open_session(...)`
- `GovernanceSession`
- `SessionPreCallResult`
- workflow diagnostics, trace, and export

PR-10c adds an optional adapter for host applications that use the OpenAI
Agents SDK runtime described by:

- OpenAI Agents guide:
  `https://developers.openai.com/api/docs/guides/agents`
- OpenAI Agents SDK repo:
  `https://github.com/openai/openai-agents-python`
- OpenAI Agents SDK docs:
  - `https://openai.github.io/openai-agents-python/`
  - `https://openai.github.io/openai-agents-python/running_agents/`
  - `https://openai.github.io/openai-agents-python/results/`
  - `https://openai.github.io/openai-agents-python/tools/`
  - `https://openai.github.io/openai-agents-python/handoffs/`
  - `https://openai.github.io/openai-agents-python/sessions/`
  - `https://openai.github.io/openai-agents-python/tracing/`
  - `https://openai.github.io/openai-agents-python/human_in_the_loop/`
  - `https://openai.github.io/openai-agents-python/ref/run_context/`

This adapter must preserve the existing AIGC ownership boundary:

- the host runs the agent SDK
- AIGC governs run boundaries and emits evidence

## 2. External Source Snapshot

The current official OpenAI material establishes the following durable runtime
surfaces:

- the SDK's small primitive set is `Agent`, tools, handoffs, guardrails, and
  `Runner`
- the main execution entrypoints are `Runner.run(...)`, `Runner.run_sync(...)`,
  and `Runner.run_streamed(...)`
- result surfaces include `final_output`, `new_items`, `last_agent`,
  `interruptions`, `raw_responses`, and `to_state()`
- tracing is built in by default, captures runs, agent activity, generations,
  tool calls, handoffs, and guardrails, and supports custom processors
- `RunConfig` exposes tracing metadata like `workflow_name`, `trace_id`, and
  `group_id`
- `RunContextWrapper.context` is local runtime context and is not sent to the
  model
- sessions are host-selected memory implementations and cannot be mixed with
  certain server-managed continuation modes
- human-in-the-loop approvals surface as `interruptions` and resume through
  `RunState`
- `Agent.as_tool(...)` differs from handoffs: it behaves like a delegated tool,
  while handoffs transfer active-agent control
- tools span multiple execution families:
  - hosted OpenAI tools
  - local/runtime tools
  - function tools
  - agents as tools
  - experimental surfaces

These observations drive the core PR-10c design choices:

- one AIGC step maps to one host-owned `Runner.run*` call
- dynamic tools must be governed during execution, not only before the run
- handoffs and `Agent.as_tool(...)` must be governed differently
- trace data is useful for evidence but is not sufficient as the sole
  governance hook

---

## 3. Problem Statement

The OpenAI Agents SDK executes a dynamic run loop:

- the active agent can change via handoffs
- tools are selected during execution
- approvals can pause the run
- trace spans are produced after the run starts

Current AIGC workflow semantics are step-centric:

- participant, transition, and protocol checks happen at step pre-call
- session tool budgets are projected from the invocation's declared
  `tool_calls`
- workflow step records are attached only when the step completes

Therefore:

- a pure post-hoc result adapter is insufficient
- a pure trace adapter is insufficient
- PR-10c needs one additive runtime seam for dynamic tool authorization
- PR-10c needs one additive workflow-step metadata seam for normalized observed
  evidence

---

## 4. Goals

PR-10c should:

- govern host applications that use the OpenAI Agents SDK runtime
- keep AIGC out of orchestration ownership
- normalize run, handoff, interruption, and tracing evidence into AIGC
  workflow metadata
- fail closed when governed binding or required evidence is missing
- support function tools and `Agent.as_tool(...)` only when AIGC can authorize
  them before execution
- preserve the adapter-free default adoption path

---

## 5. Non-Goals

PR-10c does not:

- replace the existing AIGC path for raw Responses API usage
- wrap or monkeypatch `Runner` into an AIGC-owned orchestrator
- auto-govern every OpenAI Agents feature without an explicit intercept point
- make `openai-agents` a required AIGC dependency
- persist raw trace payloads, prompts, or tool inputs by default
- support realtime/voice, sandbox agents, hosted search, hosted MCP, or other
  hosted tool surfaces in governed mode in the first cut

---

## 6. Naming And Boundary Rules

### 6.1 Public Names

Primary public names:

- `OpenAIAgentsAdapter`
- `OpenAIAgentsTracingProcessor`

Protocol-family name in AIGC policy and runtime evidence:

- `openai_agents`

This intentionally distinguishes:

- the OpenAI Agents SDK runtime
- the broader `openai` Python SDK
- raw Responses API use

### 6.2 Provider Naming Rule

`protocol="openai_agents"` identifies the orchestration/runtime family, not the
underlying model vendor.

Examples:

- a run using the Agents SDK with OpenAI Responses models is still
  `protocol="openai_agents"`
- a run using the Agents SDK with a non-OpenAI provider is still
  `protocol="openai_agents"`

Invocation artifact `model_provider` and `model_identifier` remain host-supplied
for backward compatibility. Adapter step metadata may add `models_seen` when
trace or response evidence exposes multiple models.

### 6.3 Ownership Boundary

The host still owns:

- `Runner`
- `RunConfig`
- SDK sessions
- approval decisions
- provider credentials
- transport
- retries
- persistence outside AIGC artifacts

AIGC owns:

- participant binding validation
- protocol-boundary validation
- step authorization
- dynamic wrapped-tool authorization
- additive workflow evidence
- fail-closed rejection behavior

## 7. Detailed Design Decisions

### 7.1 Step Mapping

One governed AIGC step maps to one host-owned `Runner.run(...)`,
`Runner.run_sync(...)`, or terminalized `Runner.run_streamed(...)` call.

Consequences:

- AIGC authorizes the step before the run starts
- AIGC completes the step only after the run reaches a terminal result
- internal handoffs inside the SDK run are recorded as observed evidence, not
  as independently authorized AIGC steps

### 7.2 Handoffs vs `Agent.as_tool(...)`

Handoffs are governed as observed participant-transfer evidence.

`Agent.as_tool(...)` is governed as tool activity because the manager agent
remains in control.

### 7.3 Trace Role

Trace data is used for:

- correlation
- observed agent sequence
- observed handoffs
- observed tool summaries
- usage summaries
- guardrail and interruption evidence

Trace data is not used as the only tool-governance mechanism.

### 7.4 Session Memory Role

OpenAI SDK sessions are host-owned memory. They may be recorded as metadata but
are not adopted as an AIGC-controlled session state machine.

### 7.5 First-Cut Governed Surface

Supported in governed mode:

- `Agent`
- `Runner.run(...)`
- `Runner.run_sync(...)`
- `Runner.run_streamed(...)` once the stream is drained to a terminal result
- function tools wrapped by the adapter
- `Agent.as_tool(...)` wrapped by the adapter
- handoffs declared at bind time
- SDK sessions as metadata
- custom tracing processors
- interruption pause/resume

Rejected in governed mode for the first cut:

- hosted tools
- hosted MCP
- tool search
- realtime agents
- voice pipeline
- sandbox agents
- any tool surface the adapter cannot authorize before execution

## 8. Public API Design

### 8.1 Top-Level Surface

`aegis/openai_agents_adapter.py` should publicly export:

```python
from aegis.openai_agents_adapter import (
    OpenAIAgentsAdapter,
    OpenAIAgentsParticipantBinding,
    OpenAIAgentsPreparedStep,
    OpenAIAgentsTracingProcessor,
)
```

### 8.2 Concrete Public Types

```python
from __future__ import annotations

from dataclasses import dataclass
from typing import Any, Mapping


@dataclass(frozen=True, slots=True)
class OpenAIAgentsParticipantBinding:
    participant_id: str
    agent_name: str
    role: str | None = None
    agent_metadata: Mapping[str, Any] | None = None


@dataclass(frozen=True, slots=True)
class OpenAIAgentsPreparedStep:
    session_result: SessionPreCallResult
    wrapped_root_agent: Any
    context: Any
    run_config: Any | None
    adapter_step_key: str
    invocation: Mapping[str, Any]
```

`OpenAIAgentsTracingProcessor` remains public so host applications can register
it explicitly in `RunConfig.tracing`.

### 8.3 `OpenAIAgentsAdapter` Methods

```python
class OpenAIAgentsAdapter:
    def __init__(
        self,
        *,
        trace_required_default: bool = False,
        include_sensitive_trace_data: bool = False,
    ) -> None: ...

    def bind_graph(
        self,
        *,
        root_agent: Any,
        bindings: list[OpenAIAgentsParticipantBinding],
        session: GovernanceSession,
        policy_file: str | None = None,
    ) -> None: ...

    def prepare_step(
        self,
        *,
        session: GovernanceSession,
        invocation: dict[str, Any],
        root_agent: Any,
        bindings: list[OpenAIAgentsParticipantBinding],
        step_id: str | None = None,
        participant_id: str | None = None,
        context: Any = None,
        run_config: Any | None = None,
        session_memory: Any | None = None,
    ) -> OpenAIAgentsPreparedStep: ...

    def complete_step(
        self,
        *,
        session: GovernanceSession,
        prepared: OpenAIAgentsPreparedStep,
        result: Any,
        output: dict[str, Any],
    ) -> dict[str, Any]: ...

    def register_trace_export(
        self,
        *,
        adapter_step_key: str,
        trace_summary: Mapping[str, Any],
    ) -> None: ...

    def wrap_function_tool(self, tool: Any) -> Any: ...

    def wrap_agent_as_tool(self, tool: Any) -> Any: ...
```

### 8.4 API Posture

Design rule:

- the adapter helps the host prepare and complete a governed step
- the adapter does not own the actual `Runner.run*` call

The intended host flow is:

1. build a root agent graph
2. open an AIGC session
3. call `adapter.prepare_step(...)`
4. call `Runner.run*` with the wrapped root agent and prepared context
5. call `adapter.complete_step(...)`

## 9. Internal Architecture

### 9.1 Package Layout

Planned files:

- `aegis/openai_agents_adapter.py`
- `aegis/_internal/openai_agents_adapter.py`
- `aegis/_internal/openai_agents_tracing.py`

Responsibilities:

- `openai_agents_adapter.py`
  - public exports only
- `_internal/openai_agents_adapter.py`
  - graph binding
  - run preparation
  - tool wrappers
  - result normalization
  - error mapping
- `_internal/openai_agents_tracing.py`
  - tracing processor implementation
  - trace-summary normalization

### 9.2 Internal Adapter State

The adapter needs transient in-memory state keyed by `adapter_step_key`.

```python
_active_steps: dict[str, _ActiveOpenAIAgentsStep]
```

```python
@dataclass(slots=True)
class _ActiveOpenAIAgentsStep:
    session_id: str
    step_id: str
    participant_id: str | None
    token_id: str
    root_agent_name: str
    bindings_by_name: dict[str, OpenAIAgentsParticipantBinding]
    declared_handoffs: set[tuple[str, str]]
    wrapped_tool_names: set[str]
    trace_required: bool
    session_memory_summary: dict[str, Any] | None
    dynamic_tool_calls: list[dict[str, Any]]
    trace_summary: dict[str, Any] | None
```

This state is process-local and is not part of the persisted artifact model.

### 9.3 Correlation Key

Each prepared step gets an opaque `adapter_step_key`. This is injected into
`RunContextWrapper.context` and used by:

- wrapped tools
- trace processor callbacks
- result normalization

The key must not be model-visible.

## 10. Graph Binding Model

### 10.1 Why Binding Is Required

OpenAI result and trace surfaces are name-oriented. Agent names are descriptive,
not authoritative. Governed identity requires explicit binding.

### 10.2 Binding Inputs

The adapter binds:

- `participant_id`
- trace-visible `agent_name`
- optional declared governance role
- optional agent metadata

The root agent plus all reachable governed agents must be bound.

### 10.3 Bind-Time Validation

`bind_graph(...)` must fail closed when:

- two governed agents share the same `agent_name`
- the root agent is not bound
- a bound `participant_id` is not declared in policy participants when the
  policy requires participants
- a binding role disagrees with the policy participant role constraint
- a reachable governed handoff target is unbound

### 10.4 Declared Handoff Graph

At bind time, the adapter traverses the reachable graph of governed handoffs and
computes:

```python
declared_handoffs: set[tuple[str, str]]
```

This is compared against:

- `workflow.handoffs`
- `workflow.allowed_transitions` only at the outer AIGC step level

Internal SDK handoffs are not mapped directly onto AIGC `allowed_transitions`.

### 10.5 Shared Contract Preference

If PR-10a/10b introduce shared public identity or capability types
(`AgentIdentity`, `AgentCapabilityManifest`), PR-10c should map onto them
instead of inventing OpenAI-specific public identity types.

## 11. Governed Run Sequence

### 11.1 Prepare

`prepare_step(...)` performs:

1. validate adapter import availability
2. validate the bound graph
3. validate the requested runtime surface
4. build `protocol_evidence.openai_agents`
5. inject local correlation payload into `RunContextWrapper.context`
6. wrap supported tools and `Agent.as_tool(...)`
7. call `session.enforce_step_pre_call(...)`
8. register `_ActiveOpenAIAgentsStep`
9. return `OpenAIAgentsPreparedStep`

### 11.2 Host Run

The host then performs one of:

- `Runner.run(prepared.wrapped_root_agent, input, context=prepared.context, ...)`
- `Runner.run_sync(...)`
- `Runner.run_streamed(...)`

### 11.3 Complete

`complete_step(...)` performs:

1. fetch active-step state
2. normalize result evidence
3. merge optional trace summary
4. validate observed handoffs against the declared bound graph
5. build additive `step_metadata`
6. call `session.enforce_step_post_call(..., step_metadata=...)`
7. discard active-step state

### 11.4 Failure Cleanup

On any exception after pre-call success:

- active-step state is removed
- wrapped tool state is discarded
- session token behavior follows the existing `GovernanceSession` fail-closed
  semantics

## 12. Dynamic Tool Governance

### 12.1 Why Existing AIGC Behavior Is Not Enough

Today `GovernanceSession` projects tool budgets from `invocation["tool_calls"]`
at step pre-call time.

The Agents SDK chooses tools dynamically during the run, so PR-10c needs a
runtime authorization hook.

### 12.2 Required Additive Session Method

Add:

```python
class GovernanceSession:
    def authorize_step_tool_call(
        self,
        *,
        adapter_step_key: str,
        tool_name: str,
        tool_kind: str,
        metadata: dict[str, Any] | None = None,
    ) -> None: ...
```

Behavior:

- locate the open pending step by `adapter_step_key`
- validate allowlist and session budget
- increment dynamic tool-call count for that step
- record minimal in-memory tool evidence for the step
- fail before the wrapped tool executes if governance blocks it

### 12.3 Pending-Result Data Model Change

`GovernanceSession._pending_results[token_id]` must gain:

- `adapter_step_key: str | None`
- `dynamic_tool_calls_count: int`
- `dynamic_tool_calls: list[dict[str, Any]]`

### 12.4 Counting Rule

For adapter-managed OpenAI Agents runs:

- actual wrapped tool executions count toward `max_total_tool_calls`
- the host must not also pre-populate `invocation["tool_calls"]` with the same
  adapter-managed tool names

Fail-closed rule:

- if `invocation["tool_calls"]` and adapter-managed dynamic tool counting would
  double-count the same governed tool surface, `prepare_step(...)` rejects the
  step configuration

### 12.5 Supported Governed Tool Types

Governed in PR-10c:

- wrapped `function_tool`
- wrapped `Agent.as_tool(...)`

Rejected in governed PR-10c:

- hosted tools
- hosted MCP
- tool search
- any surface without a pre-execution wrapper hook

### 12.6 Tool Wrapper Behavior

Wrapped function-tool execution:

1. read `adapter_step_key` from `RunContextWrapper.context`
2. call `session.authorize_step_tool_call(...)`
3. invoke the original tool
4. return original output unchanged

Wrapped `Agent.as_tool(...)` uses the same sequence, but sets:

- `tool_kind="agent_as_tool"`

## 13. Tracing Design

### 13.1 Trace Usage

The SDK docs describe tracing as enabled by default and wrapping runs, agents,
generations, function tools, handoffs, and guardrails. PR-10c uses that to
produce additive workflow evidence, not raw trace persistence.

### 13.2 Processor Design

`OpenAIAgentsTracingProcessor` should collect only the summary fields needed for
governance:

- `trace_id`
- `group_id`
- `workflow_name`
- ordered agent names seen
- ordered handoffs seen
- ordered tool names seen
- usage totals if available
- guardrail summary
- interruption summary

The processor should publish a compact summary through:

```python
adapter.register_trace_export(adapter_step_key=..., trace_summary=...)
```

### 13.3 Missing-Trace Rules

If `workflow.protocol_constraints.openai_agents.require_trace == true`:

- tracing must not be disabled via environment or run config
- the tracing processor must be registered
- missing trace export is a fail-closed protocol violation

If tracing is optional:

- the adapter may proceed with result-only normalization
- workflow step metadata must record `trace_present: false`

### 13.4 ZDR And Disabled Tracing

The docs note that tracing can be unavailable or disabled, including ZDR
settings. PR-10c must therefore treat trace presence as policy-controlled, not
assumed.

### 13.5 Sensitive Data Rule

The adapter must not persist raw prompts, raw outputs, or raw tool inputs by
default.

Recommended host posture:

- set `trace_include_sensitive_data=False` unless explicitly needed
- persist redacted summaries only

## 14. Run Context And Correlation

The SDK docs state that `RunContextWrapper.context` is local runtime context and
is not sent to the model. PR-10c uses it as the safe carrier for AIGC
correlation state.

### 14.1 Correlation Payload

```python
{
    "_aigc_openai_agents": {
        "session_id": "...",
        "step_id": "...",
        "participant_id": "...",
        "adapter_step_key": "...",
    }
}
```

### 14.2 Typed Context Support

If the host uses a typed context object instead of a dict, the adapter should
support:

- wrapping it in a small adapter-owned context object, or
- attaching an internal attribute when safe

The implementation must not require the host to expose AIGC data to the model
prompt or transcript.

## 15. Interruption And Approval Bridge

### 15.1 Source Behavior

The docs describe approvals as surfacing in `interruptions`, resuming through
`RunState`, and applying across function tools, handoffs, and nested
`Agent.as_tool()` runs.

### 15.2 AIGC Mapping

SDK interruption is protocol evidence, not a replacement for AIGC escalation.

Mapping rules:

- when a governed run interrupts, the adapter mirrors that state into
  `session.pause(...)`
- the same `SessionPreCallResult` remains open
- the host resolves the SDK interruption through `RunState`
- the host mirrors the approval outcome into `session.resume(...)` or
  `session.deny_approval(...)`
- the run is resumed through the same top-level agent
- the step completes only after the resumed run reaches a terminal result

### 15.3 Checkpoint Correlation

The adapter must store the generated AIGC approval checkpoint ID in:

- local adapter state
- step metadata

Fail-closed case:

- resume against a different AIGC checkpoint or stale run state rejects

### 15.4 Streaming Rule

For `Runner.run_streamed(...)`, the docs require draining `stream_events()` to
completion before inspecting interruptions. PR-10c should document that
streamed-governed runs are only terminalized after the event stream is fully
drained.

---

## 16. Sessions And Memory

### 16.1 OpenAI SDK Sessions

The SDK sessions feature is host-managed conversation memory. PR-10c records
only summary metadata, such as:

- session implementation family
- session identifier if host permits
- whether the same session is reused across interruption resume

### 16.2 AIGC Rule

SDK sessions must not be conflated with AIGC `GovernanceSession`.

### 16.3 Memory Mode Summary

`protocol_evidence.openai_agents.memory_mode` should classify:

- `none`
- `sdk_session`
- `manual_input_list`
- `responses_continuation`

The adapter does not validate the semantic correctness of host memory behavior
beyond surface compatibility checks needed for governance.

## 17. Additive AIGC Surface Changes

PR-10c requires three additive AIGC changes.

### 17.1 Policy Schema

Add:

```json
"workflow": {
  "properties": {
    "protocol_constraints": {
      "properties": {
        "openai_agents": {
          "type": "object",
          "additionalProperties": false,
          "properties": {
            "require_trace": { "type": "boolean" },
            "allow_hosted_tools": { "type": "boolean" },
            "allow_agent_as_tool": { "type": "boolean" },
            "require_unique_agent_names": { "type": "boolean" }
          }
        }
      }
    }
  }
}
```

Conservative defaults:

- `require_unique_agent_names = true`
- `allow_hosted_tools = false`
- `allow_agent_as_tool = true`
- `require_trace = false`

### 17.2 Session Tool Hook

Add `authorize_step_tool_call(...)` as defined above.

### 17.3 Step Metadata Extension

Add:

```python
def enforce_step_post_call(
    self,
    session_result: SessionPreCallResult,
    output: dict[str, Any],
    *,
    step_metadata: dict[str, Any] | None = None,
) -> dict[str, Any]:
    ...
```

Behavior:

- if `step_metadata` is provided, merge it into the emitted workflow-step record
- preserve current behavior when absent

This is additive and backward-compatible because workflow-step items are schema
generic today.

## 18. Normalized Evidence Model

### 18.1 Pre-Run `protocol_evidence`

`context["protocol_evidence"]["openai_agents"]` should contain declared or
bind-time evidence only:

```json
{
  "adapter_family": "openai_agents",
  "adapter_version": "0.9.0-beta",
  "sdk_version": "x.y.z",
  "root_agent_name": "triage_agent",
  "declared_agent_names": ["triage_agent", "billing_agent"],
  "declared_handoffs": [["triage_agent", "billing_agent"]],
  "declared_tool_surface": {
    "wrapped_function_tools": ["lookup_order", "refund_order"],
    "wrapped_agent_tools": ["ask_billing_specialist"],
    "hosted_tools_present": false
  },
  "trace_requested": true,
  "memory_mode": "sdk_session"
}
```

### 18.2 Post-Run Step Metadata

Workflow step metadata should contain summary evidence only:

```json
{
  "protocol": "openai_agents",
  "adapter_step_key": "opaque-runtime-key",
  "run_mode": "run_sync",
  "trace_present": true,
  "trace_id": "trace_123",
  "group_id": "thread_42",
  "workflow_name": "Customer support",
  "root_agent_name": "triage_agent",
  "last_agent_name": "billing_agent",
  "agent_sequence": ["triage_agent", "billing_agent"],

    {"from": "triage_agent", "to": "billing_agent"}

    "output_count": 0,

    "tool_output_count": 0

  "usage_summary": {
    "requests": 2
  },
  "models_seen": ["gpt-5.4"]

```

Do not store by default:

- raw prompt text
- raw model output text
- raw tool arguments
- raw trace export blobs

### 18.3 Workflow Trace / Export Additions

`workflow trace` and `workflow export` should surface OpenAI-adapter metadata
additively when present, but must stay backward-compatible with workflow
artifacts that lack it.

## 19. Failure Taxonomy

### 19.1 Preferred Error Families

Reuse existing families where possible:

- `WorkflowProtocolViolationError`
- `WorkflowToolBudgetExceededError`
- `WorkflowParticipantMismatchError`
- `WorkflowHandoffDeniedError`
- `InvocationValidationError`

### 19.2 New Reason Codes Only If Needed

Preferred posture:

- map to existing doctor vocabulary unless a genuinely new operator action is
  needed

Potential new codes if existing codes are insufficient:

- `WORKFLOW_OPENAI_AGENTS_BINDING_INVALID`
- `WORKFLOW_OPENAI_AGENTS_TRACE_REQUIRED`
- `WORKFLOW_OPENAI_AGENTS_UNSUPPORTED_SURFACE`

### 19.3 Fail-Closed Cases

Fail-closed cases include:

- missing `openai_agents` participant binding
- duplicate trace-visible agent names
- unsupported runtime surfaces when governed mode is required
- missing trace when trace is policy-required
- observed handoff outside the declared bound graph
- wrapped tool execution that exceeds budget or violates allowlist
- interruption resume attempted against the wrong AIGC approval checkpoint
- hosted tool or tool-search usage in governed mode
- double-count risk from predeclared plus dynamic tool accounting

## 22. Example Host Integration

```python
from agents import Agent, Runner, SQLiteSession
from aegis import AIGC
from aegis.openai_agents_adapter import (
    OpenAIAgentsAdapter,
    OpenAIAgentsParticipantBinding,
)

governance = AIGC()
adapter = OpenAIAgentsAdapter()

triage = Agent(name="triage_agent", instructions="Route the task.")
billing = Agent(name="billing_agent", instructions="Handle billing questions.")

bindings = [
    OpenAIAgentsParticipantBinding(
        participant_id="triage",
        agent_name="triage_agent",
        role="planner",
    ),
    OpenAIAgentsParticipantBinding(
        participant_id="billing",
        agent_name="billing_agent",
        role="reviewer",
    ),
]

invocation = {
    "policy_file": "policy.yaml",
    "model_provider": "openai",
    "model_identifier": "gpt-5.4",
    "role": "planner",
    "protocol": "openai_agents",
    "input": {"prompt": "Help the user with a refund."},
    "context": {},
}

sdk_session = SQLiteSession("ticket_123")

with governance.open_session(policy_file="policy.yaml") as session:
    prepared = adapter.prepare_step(
        session=session,
        invocation=invocation,
        root_agent=triage,
        bindings=bindings,
        participant_id="triage",
        session_memory=sdk_session,
    )

    result = Runner.run_sync(
        prepared.wrapped_root_agent,
        "Help the user with a refund.",
        context=prepared.context,
        session=sdk_session,
        run_config=prepared.run_config,
    )

    artifact = adapter.complete_step(
        session=session,
        prepared=prepared,
        result=result,
        output={"reply": result.final_output},
    )
```

This code sample is intentionally explicit:

- the host still owns the SDK run
- AIGC still owns the governed boundary

## 24. Design Summary

PR-10c is viable only if it is explicit about the OpenAI Agents SDK runtime:

- it is dynamic inside a run
- handoffs and `Agent.as_tool(...)` are different governance surfaces
- approvals and tracing are useful but do not replace pre-execution governance

The correct implementation is therefore:

- optional adapter
- host-owned `Runner`
- explicit participant binding
- additive session hook for dynamic wrapped-tool authorization
- additive workflow-step metadata for normalized observed evidence
- fail-closed rejection for unsupported surfaces

Anything weaker would over-claim governance coverage.
